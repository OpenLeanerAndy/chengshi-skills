## 1. 企业系统数据接入

先询问并还原用户当前获取数据的方式，再设计技术方案。采用以下优先顺序：

1. 官方且已授权的 API。
2. 从用户有权访问的网页网络请求中识别稳定接口，并确认允许自动调用。
3. 使用用户现有登录会话模拟浏览器操作。
4. 从系统导出 Excel、CSV、PDF 等文件后导入。
5. 人工录入。

用户提供网址时：

- 说明要进行的只读检查。
- 优先使用已有登录浏览器状态，不索取密码、Cookie 或验证码。
- 查看页面发出的请求、请求参数、响应字段、分页和错误返回。
- 不把偶然发现的内部接口自动视为获准使用。
- 不绕过权限、验证码、访问控制或企业安全策略。
- 页面或接口不稳定时明确记录风险和备用方案。

选择浏览器模拟操作时，记录操作步骤、等待条件、失败恢复、页面变化检测和人工接管方式。

## 2. 开发约束

- 只开发已确认 HTML PRD 中的本期范围。
- 任何需求变化先更新页面效果图和 HTML PRD，并重新确认。
- 根据项目实际情况选择技术栈，不让非技术用户选择框架。
- 优先选择易打包、易维护、能在目标环境稳定运行的方案。
- 配置和密钥放入环境配置，不写入源码或交付文档。
- 为关键操作、错误和外部请求保留必要日志。
- 不在没有明确授权时提交 Git、发布公网或修改生产系统。

## 3. 双击运行程序

默认交付目标电脑可直接双击的运行程序，不要求用户安装开发环境或运行命令：

- Windows：`.exe`
- macOS：`.app`，可通过 `.dmg` 分发

双击打开运行面板，至少提供：

- 应用名称
- 当前状态：未启动、启动中、运行中、停止中、失败
- 访问 URL
- 启动按钮
- 关闭按钮

启动按钮负责启动应用所需服务；关闭按钮负责停止服务并释放端口。运行失败时显示用户可理解的原因，并把详细信息写入日志。局域网模式显示其他同事可以访问的地址；多人使用时只在宿主电脑安装运行程序，其他人使用浏览器。

## 4. 测试矩阵

按照 HTML PRD 的验收标准建立测试，不得只验证“可以启动”。至少包含：

- 语法、类型和构建检查
- 依赖完整性
- 冷启动、重复启动、正常关闭和端口占用处理
- 每个模块的正常流程
- 每条业务规则和异常处理
- 数据保存、读取、更新和删除（适用时）
- 外部 API 或浏览器操作的成功与失败路径
- 权限和访问范围
- 页面内容、布局、颜色和交互与效果图对照
- Windows 或 macOS 双击运行包
- 本机、局域网或公网实际访问
- 临时文件和测试数据清理

保存测试命令、结果和必要截图。测试项不适用时写明原因，不得用“未测试”冒充通过。

## 5. 部署和试用

1. 检查部署目标、配置、端口、访问范围和数据目录。
2. 备份会被覆盖的现有配置或数据。
3. 部署并启动应用。
4. 从用户实际使用的设备打开访问 URL。
5. 执行核心冒烟测试。
6. 提供双击启动包、访问地址和简短使用说明。
7. 请用户实际试用。
8. 对试用问题先判断是否偏离已确认 PRD；修复后重新测试和部署。

公网、生产服务器、域名解析或证书变更属于外部状态操作，执行前取得明确授权并准备回退方案。
