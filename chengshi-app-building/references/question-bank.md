# 访谈问题库

按需选择问题，不要机械逐条询问。每轮只问一个主要问题；用户已回答的内容直接记录并跳过。不要把相邻问题合并成一句，尤其不得同时询问“谁使用”和“在哪里访问”。

## 1. 开场

严格分成两轮：

1. `你想做一个什么应用？`
2. `这件事现在是怎么做的，哪些地方让你觉得麻烦或不舒服？`

回答不清或流程复杂时使用：

- `你现在实际做一次时是怎么操作的？可以从打开哪个系统、文件或网页开始说。`
- `完成这一步以后，你接下来会做什么？`
- `方便的话，可以提供脱敏后的截图、样例文件或页面网址吗？不要发送账号和密码。`

## 2. 用户和访问

- 先单独问：`这个应用是只有你自己用，还是其他同事也要一起用？`
- 得到回答后再单独问：`大家是在同一个办公室网络里使用，还是在家、出差时也需要使用？`
- `不同的人能看到和操作的内容都一样吗？`
- `大家需要使用同一份数据，还是各自保存自己的数据？`
- 多人坚持本地应用时：`每个人可能都要单独安装和更新，数据也可能分散，这些问题你能接受吗？`

不要固定询问使用人数或并发。仅在限额、抢单、多人同时修改、长时间 AI 任务或用户明确担心速度时追问实际冲突场景。

## 3. 最终结果

- `事情处理完成后，你最希望看到或得到什么？`
- `这个结果由谁查看或接收？`
- `以后还需要回来查以前的结果吗？`

## 4. 识别大模块

- `这个应用大体上需要包含哪些部分？`
- 复述后：`我把它分成这些大模块，和你的理解一致吗？`

大模块必须可以独立描述主要业务目标、数据和完整流程，并可以单独验收。以下通常只是同一模块内的步骤：导入数据、计算、生成结果、导出、通知。

只有确认的大模块达到 3 个时才问：

- `为了尽快做出能使用的版本，第一期建议先做好最重要的一两个模块，你最希望先做哪个？`

少于 3 个大模块时，不提分期。

## 5. 每个模块的固定起点

第一个问题必须是：

- `你希望在这个模块里做哪些事情？`

从回答中同时提炼功能操作与工作流，不要求用户按指定格式回答。随后按缺口选择：

- `这件事通常由谁开始？`
- `如果一切顺利，第一步做什么？`
- `完成这一步以后，接下来由谁做什么？`
- `做到什么程度，这件事就算完成？`
- `最后会产生什么结果？`

## 6. 数据

不要先让用户凭空枚举字段。先根据流程推导并用业务语言验证：

- `完成这个模块，我判断需要用到这些数据：A、B、C。和你真实工作中的情况一致吗？`
- `这些数据你现在分别是怎么拿到的？`
- `哪些是人工填写，哪些来自 OA、Excel、邮件或其他系统？`
- `你平时是在系统页面查看、搜索后复制，还是先导出文件？`
- `可以把平时使用的页面网址发给我吗？不要发送账号和密码。`
- `处理后的结果只在新应用里保存，还是还要写回原来的系统？`
- `这些数据以后还需要查询吗？`
- `方便提供一份脱敏样例吗？`

用户给出网址后，先说明将进行只读检查。在授权范围内查看页面和网络请求，优先寻找稳定、允许使用的 API；没有合适接口时再考虑浏览器模拟操作，最后才采用文件导入或人工录入。

## 7. 规则

- `什么情况下这件事算完成或通过？`
- `哪些条件是必须满足的？`
- `几个判断结果不一样时，哪个优先？`
- `哪些情况必须由人决定？`
- `你现在人工处理时，是根据什么做决定的？可以拿一个真实例子说。`

没有特殊规则时也要记录“无特殊业务规则”，证明已经考虑。

## 8. 页面和输出

- `在这个模块里，用户最需要看到哪些页面或内容？`
- `用户打开这个页面后，最重要的操作是什么？`
- `需要在手机上使用吗？`
- `有没有现成系统、截图或手绘图可以参考？`

## 9. 模块确认

输出完整模块需求卡，包含：

1. 模块要解决的业务问题
2. 用户和权限
3. 功能操作
4. 正常工作流
5. 数据及来源
6. 业务规则
7. 页面和输出
8. 与其他模块或系统的关系
9. 暂未确认内容

最后只问：

- `以上是我对“模块名称”的完整理解，有没有需要修改或补充的地方？`

修改后重新输出完整模块卡；得到明确确认后才能进入下一个模块。

## 10. 异常情况

所有本期模块的正常需求确认后，再按模块主动识别并逐个询问：

- 数据缺少或格式错误
- 重复提交或重复处理
- 用户取消或中途退出
- 权限不足
- 外部系统、网络或 API 不可用
- 浏览器自动操作失败或页面变化
- 多人修改同一条数据（仅实际存在时）
- 少见但后果严重的业务错误

提问格式：

- `如果发生【具体情况】，你希望系统怎么处理？我建议【简单方案】，可以吗？`

## 11. 设计要素

异常处理确认后再问：

- `这个应用有没有指定的主题色？`
- `有没有需要使用的 Logo？如果有，可以把文件发给我。`
- `有没有希望参考的页面风格？`

用户没有偏好时，提供一套符合业务场景的配色和样式建议，请用户确认。

## 12. 运行与交付

- `最终负责运行这个应用的电脑是 Windows 还是 Mac？`
- `应用准备只在这台电脑使用、供同一网络的同事访问，还是通过公网访问？`

默认交付双击运行程序和控制面板。不要要求普通用户执行命令或安装开发依赖。
