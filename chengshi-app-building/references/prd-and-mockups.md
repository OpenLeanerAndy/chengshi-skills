# 页面效果图与 HTML 产品需求说明书

## 目录

1. 页面效果图顺序
2. 效果图质量标准
3. HTML PRD 内容结构
4. 确认循环

## 1. 页面效果图顺序

1. 从所有已确认模块中提取完整页面清单。
2. 标注每个页面的使用角色、目的、主要操作、数据状态和前后跳转。
3. 先确定通用导航、主题色、Logo、字体、间距和组件风格。
4. 优先用 HTML/CSS 制作可实现的高保真静态原型，再用浏览器截图生成 PNG 效果图。
5. 使用真实字段和代表性示例数据；至少覆盖正常状态，关键空状态或错误状态按需求补充。
6. PC 和移动端都在范围内时，为关键页面分别出图。
7. 先把效果图展示给用户，按页收集意见并更新。
8. 用户确认后，把最新图片嵌入 `产品需求说明书.html`。

不要用无法落地的概念插画代替页面效果图。开发阶段应能直接根据原型结构、组件和样式实现。

## 2. 效果图质量标准

- 页面内容与确认的功能、字段、规则完全一致。
- 同一应用的导航、颜色、按钮、表格和表单风格一致。
- 包含用户完成主要任务所需的全部操作入口。
- 关键状态有清晰反馈：待处理、处理中、成功、失败、无数据等。
- 使用清晰中文文案，不保留 Lorem ipsum 或无意义占位符。
- 不擅自增加 PRD 未确认的功能。
- 图片清晰、比例合理，并使用相对路径嵌入 HTML 以便离线查看。

## 3. HTML PRD 内容结构

文件名必须为 `产品需求说明书.html`，可参考 `assets/prd-template.html`。至少包含：

1. 文档标题、版本、状态和更新时间
2. 需求分析
   - 应用是做什么的
   - 当前怎么做
   - 当前痛点
   - 最终输出
   - 用户是谁
   - 使用与访问方式
   - 参考案例
3. 本期范围与后续规划
4. 应用定义
   - 大模块清单
   - 每个模块的功能操作
   - 正常操作流程
   - 模块间关系
5. 业务规则
6. 异常情况与处理方式
7. 应用数据
   - 数据项
   - 来源
   - 用户当前获取方式
   - 推荐获取方式
   - 保存与更新方式
8. 界面设计
   - 通用设计规范
   - 主题色和 Logo
   - 页面清单
   - 每个页面效果图
   - 页面说明与交互
9. 技术要求
   - 技术方案及业务原因
   - 企业系统/API/浏览器操作方案
   - 安全与权限
   - 日志和配置
10. 运行与部署
    - 本机、局域网或公网
    - Windows `.exe` 或 macOS `.app`/`.dmg`
    - 运行面板：状态、URL、启动、关闭
11. 验收标准和测试用例
12. 不在本期实现的内容
13. 需求确认记录

把用户提供和确认的全部内容写入适当章节。不要为了版面简洁删掉字段、规则、异常或流程步骤。

## 4. 确认循环

1. 先确认页面效果图。
2. 生成完整 HTML PRD。
3. 提供可点击文件链接并请用户审阅。
4. 收到修改意见后，先更新需求台账。
5. 涉及界面时先更新效果图，再更新 HTML。
6. 重新检查所有章节和图片。
7. 重复直到用户明确确认可以开发。
8. 在确认记录中写入确认日期和最终范围。
